# AstraTrade AI Phase 4 页面与用户流程说明

## 1. 设计原则

- 简体中文优先，桌面优先，同时保证手机端能完成查看和停止操作；
- 每个页面明确标注“模拟交易”；
- 所有金额同时显示单位；
- 风控、行情失败和空数据必须给出可行动的说明；
- 页面不暴露 Token、内部 ID、服务器地址或内部错误堆栈。

## 2. 信息架构

```text
控制台
├── 总览
│   ├── 净值与收益
│   ├── 账户资产
│   ├── 最近订单
│   └── 最近通知
├── Agent 配置
│   ├── 策略模板
│   ├── 自定义预算与频率
│   └── 启动/停止
├── 活动记录
│   ├── 模拟订单
│   ├── 风控事件
│   └── 审计事件
├── 通知中心
├── 数据导出
└── 账户设置
    ├── 测试连接
    ├── 撤销连接
    └── 修改密码
管理员
└── 运行概览
    └── 邀请码管理
```

## 3. 核心流程

### 3.1 首次使用流程

```text
登录
  ↓
总览空状态
  ↓
进入 Agent 配置
  ↓
选择“保守定投”模板
  ↓
确认模拟口径与预算
  ↓
启动 Agent
  ↓
立即执行一次模拟定投
  ↓
总览展示订单、净值和通知
```

关键要求：启动前必须展示预算、频率、手续费和“不会使用真实资金”的说明。

### 3.2 配置 Agent 流程

1. 用户打开 Agent 配置页；
2. 页面加载当前配置和服务端上限；
3. 用户选择模板，或切换为自定义；
4. 用户修改预算/频率；
5. 前端展示预计资金占用；
6. 服务端再次校验预算与频率；
7. 保存成功后显示新的配置；
8. 配置保存失败时保留用户输入并显示原因。

### 3.3 查看订单详情流程

```text
活动记录
  ↓
点击模拟订单
  ↓
订单详情抽屉/页面
  ├── 执行原因
  ├── 行情与数量
  ├── 手续费
  ├── 账户变化
  └── 风控结果
```

订单不存在、无权限或已被删除时，统一显示“订单不存在或无权查看”，不得泄露其他用户是否存在该订单。

### 3.4 风控拦截流程

```text
Agent 到达执行时间
  ↓
行情有效性检查
  ↓
预算与余额检查
  ↓
幂等键检查
  ├── 通过 → 模拟成交 → 更新净值 → 生成通知
  └── 拦截 → 不扣余额 → 记录原因 → 生成风控通知
```

用户可看到的原因包括：余额不足、价格无效、行情过期、重复执行和预算超过上限。

### 3.5 通知流程

- 通知中心显示未读数量；
- 首次进入时按时间倒序展示；
- 点击通知后标记为已读；
- 相关通知跳转到订单详情、Agent 页面或活动记录；
- 批量标记已读后，未读数立即更新。

### 3.6 数据导出流程

1. 用户进入数据导出页；
2. 选择数据类型和时间范围；
3. 页面展示导出范围和模拟数据提醒；
4. 用户确认导出；
5. 服务端按当前用户权限生成文件；
6. 记录导出审计事件；
7. 浏览器下载文件；
8. 无数据时下载带表头的空文件，并明确提示。

## 4. 页面状态规范

每个数据页必须覆盖：加载中、成功、有数据、无数据、请求失败、权限不足、会话过期。

| 状态 | 页面行为 |
| --- | --- |
| 加载中 | 显示骨架或明确加载提示，禁止误显示 0 |
| 无数据 | 解释为什么为空，并给出下一步操作 |
| 请求失败 | 显示用户可理解的原因和重试入口 |
| 403 | 显示无权限，不显示资源存在性 |
| 401 | 清理本地状态并返回登录页 |
| 风控拦截 | 明确“不扣款、不成交”，显示原因 |

## 5. 移动端关键路径

在窄屏下必须可完成：

- 查看净值和最近订单；
- 启动 Agent；
- 停止 Agent；
- 查看风控拦截；
- 打开订单详情。

表格允许横向滚动，但停止 Agent 按钮、风险状态和净值摘要不能被隐藏在横向滚动区域内。

## 6. 管理员流程

管理员进入运行概览后只能查看聚合数据；邀请码管理仍然保持创建、停用和使用次数查看。管理员尝试访问用户级订单详情时必须经过明确的权限设计，Phase 4 默认不开放。
