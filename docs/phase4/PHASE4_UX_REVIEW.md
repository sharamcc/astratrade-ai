# AstraTrade AI Phase 4 体验评审与交互规范

## 1. 评审结论

首版控制台的核心流程可用，但必须优先改善三类体验问题：

1. 移动端需要能够完成查看总览、启动/停止 Agent 和查看风控原因；
2. 写操作必须明确显示进行中、成功或失败状态，避免用户重复点击；
3. 审计事件在用户界面中必须使用可理解的中文标签，内部事件名只保留在审计数据中。

## 2. 页面体验规范

| 页面 | 首要任务 | 必须看到的信息 | 空状态/失败状态 |
| --- | --- | --- | --- |
| 登录/注册 | 完成身份验证 | 邮箱、密码、邀请码要求 | 错误原因紧邻表单，使用可读文案 |
| 总览 | 判断账户和 Agent 状态 | 净值、余额、持仓、盈亏、通知、最近成交 | 无订单时说明如何启动 Agent |
| Agent | 保存策略并启停 | 预算、频率、风控上限、模拟标识 | 保存/启动/停止有明确反馈，重复提交被禁用 |
| 活动记录 | 追踪执行过程 | 订单、手续费、审计时间线 | 无数据时说明首次启动路径 |
| 通知中心 | 处理重要事件 | 未读数、事件原因、关联详情入口 | 已读状态刷新后保持 |
| 设置 | 管理连接和密码 | 测试连接状态、密码修改结果 | OAuth 失败和密码错误不能丢失上下文 |
| 管理后台 | 管理测试资格 | 用户数、运行概况、邀请码状态 | 无邀请码时显示创建入口 |

## 3. 交互状态

- 所有写按钮在请求进行时禁用，并保留当前页面上下文。
- 成功状态使用绿色提示，失败状态使用红色提示，风险拦截使用黄色提示。
- 错误提示使用 `role=alert`；异步成功提示使用 `aria-live=polite`。
- 移动端宽度小于 600px 时，侧栏转为顶部导航，卡片和表格允许横向滚动。
- 模拟交易标识必须在登录后总览、Agent 和订单详情中保持可见。

## 4. 术语规范

- “模拟成交”表示仅更新模拟账本，不向 OKX 提交真实订单。
- “风控拦截”表示没有成交、没有扣款。
- “行情失效”表示本次执行跳过，等待后续计划重试。
- 手续费统一显示为按 0.1% 模拟计算。

## 5. 发布前体验门槛

- 桌面端核心流程无 P0/P1 体验缺陷；
- 移动端可完成登录、查看总览、停止 Agent；
- 所有核心写操作均有成功/失败反馈；
- 所有展示给用户的审计事件都有中文标签或明确的可读兜底文案。
