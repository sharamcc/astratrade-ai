# AstraTrade AI Phase 4 验收测试剧本

## 1. 测试目标

验证用户能够完成一次可理解、可追踪、可导出的模拟定投；验证风控、权限、通知、数据分析和管理员概览不破坏现有安全边界。

本剧本不包含真实资金、真实下单或生产 OAuth Provider。

## 2. 测试角色与前置条件

角色：

- 管理员：可创建和停用邀请码，可查看聚合运行概况；
- 普通用户 A：只能访问自己的模拟账户；
- 普通用户 B：用于验证数据隔离。

前置条件：

- 测试环境服务、Worker 和数据库备份任务正常；
- 已配置测试行情适配器；
- 准备一个有效邀请码、一个已耗尽邀请码和一个已停用邀请码；
- 测试账户初始模拟余额为 10,000 USDT；
- 测试数据明确标注为模拟数据。

## 3. 端到端主剧本

### E2E-01 管理员创建邀请码

1. 管理员登录；
2. 打开管理员运行概览；
3. 创建一个单次邀请码；
4. 复制邀请码并记录创建时间；
5. 刷新页面。

期望：邀请码仍显示，使用次数为 0，状态为有效，且不会在页面中显示明文历史邀请码。

### E2E-02 用户注册与首次配置

1. 用户 A 使用邀请码注册；
2. 登录控制台；
3. 打开 Agent 配置；
4. 选择“保守定投”模板；
5. 保存每日 100 USDT 配置。

期望：注册成功、初始余额正确、配置保存成功；超过 500 USDT 的预算被拒绝；页面明确标注模拟交易和 0.1% 模拟手续费。

### E2E-03 启动并完成模拟执行

1. 用户 A 点击启动 Agent；
2. 等待执行结果；
3. 返回总览；
4. 查看净值曲线和最近订单；
5. 打开订单详情。

期望：Agent 进入运行状态，产生一笔模拟成交；余额、BTC、净值和手续费更新；订单详情能解释执行原因和账户变化；不得产生真实交易请求。

### E2E-04 风控拦截

1. 将测试账户模拟余额降低到不足以支付预算和手续费；
2. 触发一次 Agent 执行；
3. 打开总览和活动记录。

期望：执行被拦截，不产生订单、不扣余额；页面显示明确原因并标注“未成交”；生成一条风控通知和审计事件。

### E2E-05 行情失效

1. 让行情适配器返回过期或无效价格；
2. 触发 Agent 执行。

期望：执行被跳过；不扣余额、不生成成交订单；页面说明行情失效；审计记录包含行情年龄或失效原因。

### E2E-06 通知中心

1. 用户查看未读通知数；
2. 打开成交通知和风险通知；
3. 点击通知跳转到订单或活动记录；
4. 批量标记已读。

期望：未读数准确减少，跳转目标正确，刷新后已读状态保持；同一执行不会生成重复通知。

### E2E-07 数据导出

1. 选择订单 CSV；
2. 选择净值 CSV；
3. 选择审计记录 CSV；
4. 下载 Agent 配置 JSON；
5. 用户 B 尝试访问用户 A 的导出资源。

期望：文件可打开、字段完整并标注模拟数据；导出事件被记录；用户 B 无法读取用户 A 的数据。

### E2E-08 停止与安全操作

1. 用户停止 Agent；
2. 确认下次执行时间被清空；
3. 撤销 OKX 测试连接；
4. 修改密码；
5. 使用旧会话访问写接口。

期望：Agent 不再执行，连接状态变为未连接；密码修改后旧会话失效；CSRF 缺失或不匹配的写请求仍返回 403。

## 4. 权限与隔离测试

| 编号 | 操作 | 期望 |
| --- | --- | --- |
| SEC-01 | 用户 A 请求用户 B 的订单 ID | 返回无权限或不存在，不泄露详情 |
| SEC-02 | 普通用户访问管理员概览 | 返回 403 |
| SEC-03 | 未登录请求 Dashboard | 返回 401 |
| SEC-04 | 写请求缺少 CSRF | 返回 403，不改变数据 |
| SEC-05 | 重复提交相同执行键 | 只产生一笔订单 |
| SEC-06 | 导出他人数据 | 返回 403 或空权限结果，不生成文件 |

## 5. 前端测试

- 桌面端验证总览、Agent、活动、通知、设置和管理员页面；
- 移动端验证查看净值、启动 Agent、停止 Agent、查看风险原因；
- 验证加载中、空数据、网络失败、401、403 和 429 状态；
- 验证金额、数量、时间和手续费格式；
- 验证按钮重复点击不会重复提交；
- 验证刷新后筛选条件和已读状态符合设计。

## 6. 非功能验收

- HTTP 自动跳转 HTTPS；
- Cookie 的 `HttpOnly`、`Secure`、`SameSite=Lax` 属性正确；
- API 和 Worker 重启后服务可恢复；
- 数据库迁移可重复执行；
- 部署前有可恢复的 SQLite 备份；
- 日志不包含密码、Session、OAuth Token；
- 单用户数据不会出现在另一用户的 API 响应中。

## 7. 发布门槛

只有同时满足以下条件才允许扩大测试范围：

1. E2E-01 至 E2E-08 全部通过；
2. SEC-01 至 SEC-06 全部通过；
3. 前端桌面端和移动端关键路径通过；
4. 备份恢复演练通过；
5. 无 P0/P1 未关闭缺陷；
6. 至少 3 名内部测试用户完成主流程；
7. 产品、开发和安全评审人共同确认测试报告。

## 8. 缺陷分级

- P0：跨用户数据泄露、真实交易误触发、余额错误扣减；立即阻断发布；
- P1：Agent 重复成交、风控绕过、密码/会话失效、导出越权；修复后才能发布；
- P2：页面错误、通知延迟、统计不准确但不影响资金模型；可进入下一迭代；
- P3：文案、视觉和非关键交互问题；记录后排期。
