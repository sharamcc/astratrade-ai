# AstraTrade AI Strategy V2 产品 PRD

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品 | AstraTrade AI |
| 版本 | Strategy V2 |
| 目标 | 在模拟交易环境中逐步引入均线、网格和组合定投策略 |
| 用户 | 受邀请码邀请的测试用户、管理员 |
| 发布边界 | 仅模拟交易，不接入真实资金、不开放手动下单 |

## 2. 背景与目标

当前产品只有保守定投 Agent。下一版本需要让用户能够比较不同策略的行为、风险和模拟结果，同时保持服务端风控、账本幂等和多用户隔离不变。

核心目标：

- 建立统一策略配置、信号、执行和审计模型；
- 分阶段上线均线策略、网格策略和组合定投策略；
- 让每次模拟执行都能解释“为什么产生信号、为什么成交或被拦截”；
- 让用户比较策略收益、手续费、回撤和风险拦截次数。

## 3. 范围

### 3.1 本阶段包含

- 策略模板的创建、复制、编辑、停用和版本标识；
- 均线策略：短周期/长周期交叉信号；
- 网格策略：区间、网格数量和单格预算；
- 组合定投：多个标的及其预算比例；
- 策略执行记录、风控决策、模拟订单和通知；
- 策略表现和风险指标展示；
- 服务端参数校验、预算上限和重复执行保护。

### 3.2 明确不包含

- 真实资金、真实下单、手动下单；
- 合约、杠杆、借贷、做空；
- 自动切换生产 OAuth Provider；
- 用户自定义脚本或任意代码执行；
- 面向公众的收益排名或投资建议。

## 4. 分阶段发布

### V2.1 策略基础层

- 统一策略接口和配置版本；
- 统一信号格式：`buy`、`sell`、`hold`、`skip`；
- 统一执行上下文、风险决策和审计字段；
- 现有定投策略迁移为统一策略实现，行为保持兼容。

### V2.2 均线策略

用户配置短周期、长周期、单次预算和冷却时间。

规则：

- 短均线上穿长均线产生买入信号；
- 短均线下穿长均线产生卖出信号；
- 金额、持仓、冷却时间和每日亏损均经过服务端风控；
- 页面显示均线值、当前信号和触发原因。

### V2.3 网格策略

用户配置下界、上界、网格数量、单格预算和突破处理方式。

规则：

- 价格触及下方网格时产生买入信号；
- 价格触及上方网格时产生卖出信号；
- 区间外暂停新网格执行并生成通知；
- 网格重算必须生成新版本，不能复用旧执行键。

### V2.4 组合定投

用户配置标的、固定金额或比例、执行频率和组合预算。

规则：

- 每个标的独立生成信号和风险决策；
- 组合总预算不能超过服务端上限；
- 单个标的行情失败时跳过该标的，不影响其他标的；
- 页面展示组合净值、持仓占比、手续费和各标的执行状态。

## 5. 用户故事

- 作为用户，我可以选择一个策略模板并查看它的参数含义。
- 作为用户，我可以保存策略版本并知道当前运行的是哪个版本。
- 作为用户，我可以看到每次执行的信号来源、风控结果和账户变化。
- 作为用户，我可以停止策略，停止后不再生成新的执行任务。
- 作为管理员，我可以查看各策略的聚合运行情况，但不能读取用户级私密交易数据。

## 6. 产品指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 策略配置完成率 | 进入策略页后成功保存配置的用户比例 | ≥ 80% |
| 首次执行成功率 | 启动后产生有效执行结果的比例 | ≥ 95% |
| 可解释执行率 | 有完整信号、风控和账本快照的执行比例 | 100% |
| 重复成交数 | 相同执行键生成的重复订单数 | 0 |
| 风控绕过数 | 未经过服务端风控的订单数 | 0 |
| 用户隔离缺陷 | 跨用户读取或导出数据的事件数 | 0 |

## 7. 交互要求

- 所有策略页面明确显示“模拟交易”标识；
- 保存、启动、停止和停用操作显示进行中、成功或失败状态；
- 参数超过限制时在表单处说明原因，服务端再次校验；
- 执行详情显示策略版本、信号、行情时间、风控结果、手续费和账户变化；
- 移动端可完成查看、启动和停止策略。

## 8. 发布门槛

- 三种策略均通过单元、API、权限隔离和浏览器主流程测试；
- 现有定投用户数据迁移后余额、订单和审计记录不变；
- 任何策略都不能绕过服务端风控或账本幂等；
- 至少三名内部测试用户完成每个已发布策略的模拟主流程；
- 无 P0/P1 缺陷后才允许扩大邀请码发放范围。
